# Безопасность — MarketMind AI

## Управление секретами

- **Никогда** не коммитьте `.env` файлы. Используйте `.env.example` как шаблон.
- Все ключи (`BOT_TOKEN`, `ANTHROPIC_API_KEY`, `GROK_API_KEY`, пароли БД) хранятся **только** в `.env`.
- В продакшене используйте secrets-менеджер (Vault, AWS Secrets Manager, Docker secrets).
- Прокси-строки (`COMMON_PROXY`, `PARSER_PROXY`) содержат логины/пароли — храните их аналогично.
- В логах и отчётах **никогда** не выводите токены и ключи API.

## ADMIN_IDS

- Список `ADMIN_IDS` определяет, кто имеет полный доступ к управлению ботом.
- В production **обязательно** укажите хотя бы одного администратора.
- Пустой `ADMIN_IDS` разрешает доступ **всем** пользователям — это допустимо только для локальной разработки.
- Telegram user ID можно получить через `@userinfobot`.

## Безопасность прокси

- Прокси-строки могут содержать credentials — не логируйте их в открытом виде.
- При использовании прокси для Telegram: убедитесь, что прокси-сервер не логирует содержимое запросов.
- SOCKS5-прокси предпочтительнее HTTP для шифрования трафика.
- Периодически проверяйте работоспособность прокси — нерабочий прокси не блокирует бота, но может ухудшить качество парсинга.

## Rate Limiting

- Параметры `RATE_LIMIT_WB_*` и `RATE_LIMIT_OZON_*` контролируют задержки между запросами.
- Не снижайте значения ниже рекомендованных — маркетплейсы активно блокируют агрессивных парсеров.
- Adaptive cooldown автоматически увеличивает задержки при обнаружении блокировок.
- При ручном изменении параметров resilience (`CIRCUIT_BLOCK_THRESHOLD`, `COOLDOWN_STEPS_MINUTES`) тестируйте на малом объёме.

## Валидация входных данных

- Все пользовательские URL проходят валидацию через `_normalize_proxy()` и парсеры.
- Telegram-команды парсятся через `aiogram` с валидацией аргументов.
- Файлы загружаются через бота с проверкой расширения (`.xlsx`, `.csv`).
- SQL-инъекции невозможны при использовании SQLAlchemy (параметризованные запросы).

## Playwright и браузер

- Proxmox-режим (`OZON_HEADLESS=0`) используется **только** для ручного входа в Ozon.
- Persistent profile хранит cookies — не коммитьте и не публикуйте `app/data/ozon_profile/`.
- При использовании в Docker: Playwright запускается в headless-режиме с minimal-опциями.

## Общие рекомендации

- Не храните в репозитории: `.env`, `*.db`, `*.log`, `app/data/ozon_profile/`, `*.pem`, `*.key`.
- Используйте `pre-commit` хуки для проверки секретов перед коммитом.
- Регулярно обновляйте зависимости (`pip install --upgrade`) — известные уязвимости исправляются в новых версиях.
- В production: ограничьте сетевой доступ контейнера только необходимыми хостами.
