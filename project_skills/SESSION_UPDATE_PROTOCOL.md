# Session Update Protocol

Протокол обновления skillpack после завершения сессии. Этот файл является обязательным к прочтению перед финальным ответом агента.

## Когда выполнять

Протокол активируется:

1. Автоматически — перед финальным ответом в конце каждой сессии (см. `AGENTS.md`).
2. По команде пользователя — `skillpack session close`.
3. После существенных изменений кодовой базы (парсеры, workflow, database, CLI).

## Шаг 1. Чтение контекста сессии

1. Определить, какие файлы были созданы, изменены или удалены за сессию.
2. Определить, какие skill ID были применены или упомянуты.
3. Определить, были ли выявлены новые паттерны, обходные пути, regression-уроки или архитектурные решения.
4. Проверить, были ли ошибки или блокеры и как они были решены.

## Шаг 2. Поиск reusable patterns

Ищите повторно используемые паттерны среди:

- **Новые command/workflow** — если добавлена новая команда бота или pipeline.
- **Решения ошибок** — если баг был исправлен уникальным способом, который может повториться.
- **Workaround-ы** — обходные пути для ограничений marketplace, API или библиотек.
- **Regression-уроки** — тесты, покрывающие повторяющиеся проблемы.
- **Архитектурные решения** — выбор между альтернативами с обоснованием.
- **Конфигурационные паттерны** — новые переменные окружения, профили, настройки.
- **Телеметрия и диагностика** — новые метрики, логи, способы мониторинга.

## Шаг 3. Обновление skills_database.md

Если обнаружен reusable pattern:

1. Проверить, существует ли похожий скилл в `skills_database.md`.
2. Если существует — обновить его (добавить новые поля, примечания, примеры кода).
3. Если не существует — создать новый скилл с полями:
   - ID скилла (уникальный, kebab-case)
   - Категория
   - Краткое описание
   - Когда использовать
   - Где найден (файлы и функции)
   - Зависимости
   - Входные данные
   - Выходной результат
   - Пошаговый алгоритм
   - Правила качества
   - Типичные ошибки
   - Антипаттерны
   - Production рекомендации
   - Возможность переиспользования
   - Уровень сложности
   - Maturity
   - Теги

## Шаг 4. Обновление skills_index.json

После обновления `skills_database.md`:

1. Добавить или обновить запись в `skills["skills"]` массиве.
2. Указать `id`, `title`, `category`, `complexity`, `maturity`, `priority`.
3. Указать `dependencies` и `dependents` (согласно `skills_database.md`).
4. Указать `source_paths` — реальные файлы где реализован скилл.

## Шаг 5. Pending proposals

Если недостаточно информации для полноценного скилла:

1. Создать файл в `project_skills/session_updates/` с именем `YYYY-MM-DD-<topic>.md`.
2. Описать: что обнаружено, почему это reusable, какой скилл может потребоваться.
3. Пометить статус `pending`.

## Шаг 6. Валидация

После всех изменений запустить:

```bash
python project_skills/validate_skills.py
```

Валидатор проверяет:

- Соответствие ID между `skills_database.md` и `skills_index.json`.
- Наличие обязательных полей.
- Отсутствие дублирующихся ID.
- Целостность зависимостей.

## Шаг 7. Финальный отчёт

В финальном ответе сессии указать:

- Какие скиллы были обновлены или добавлены.
- Были ли созданы pending proposals.
- Если reusable patterns не обнаружены — явно указать это.

## Пример отчёта

```
Skillpack update:
- Updated: `parser-ozon-product-extraction` (added DOM snapshot strategy)
- Added: `telegram-card-research` (new skill for competitor research workflow)
- Pending: `2026-07-09-wb-batch-export.md` (batch WB export not yet full skill)
- Validation: OK (49 skills, 0 drift)
```
