# Development Plan — MarketMind AI Core

План работ разбит на этапы от стабилизации текущего прототипа до продукта, пригодного для обычного пользователя.

## Этап 1 — Привести текущий прототип в рабочее состояние

### Цель

Сделать так, чтобы проект можно было стабильно запускать и тестировать в предсказуемой среде.

### Конкретные задачи

- восстановить нормальное Python-окружение;
- обеспечить наличие `pip` и зависимостей в рабочем venv;
- устранить зависание инициализации БД;
- проверить, что CLI запускается без скрытых падений;
- отделить runtime-артефакты от исходников;
- обновить документацию под фактический статус.

### Файлы, которые потребуется создать или изменить

- `app/database.py`
- `app/config.py`
- `app/main.py`
- `tests/test_database.py`
- `tests/helpers.py` при необходимости
- `README.md`
- `docs/PROJECT_AUDIT.md`
- `.gitignore`

### Критерии готовности

- `python3 -m pytest` работает в нормальной среде;
- `Database.init()` не зависает;
- запуск CLI не требует ручного шаманства;
- runtime clutter не смешивается с исходниками;
- документация честно отражает текущее состояние.

### Риски

- async SQLite/aiosqlite может вести себя нестабильно в конкретной среде;
- попытка “починить всё сразу” приведёт к лишнему рефакторингу;
- можно случайно затронуть рабочие parser/card flows.

### Тесты

- `tests/test_database.py`
- `tests/test_config.py`
- `tests/test_cli.py`
- `tests/test_worker.py`
- `tests/test_parsers.py`

## Этап 2 — Удобный импорт товаров

### Цель

Сделать простой и понятный импорт Excel/CSV/PDF/ссылок без технических знаний.

### Конкретные задачи

- отдельный мастер импорта;
- распознавание колонок;
- проверка обязательных полей;
- подсказки по недостающим данным;
- сопоставление строк с товарами.

### Файлы

- новый модуль импорта, например `app/importer.py` или `app/ingest.py`
- `app/batch_enricher.py`
- `app/card_filler.py`
- `tests/test_importer.py`

### Критерии готовности

- пользователь загружает файл и видит разобранные товары;
- ошибки объясняются простым языком;
- импорт можно повторить без потери данных.

### Риски

- слишком ранняя поддержка всех форматов;
- смешивание import UI и business logic;
- дублирование логики с BRD enrichment.

### Тесты

- импорт CSV;
- импорт XLSX;
- пустые/битые столбцы;
- неполные строки;
- повторный импорт.

- Ozon API adapter;

- isolation tests.

## Общий принцип

Не переписывать проект целиком. Каждый этап должен завершаться:

1. минимальным набором изменений;
2. тестами;
3. честной документацией;
4. отсутствием скрытых регрессий.
