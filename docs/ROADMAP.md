# Roadmap — MarketMind AI

> Дорожная карта развития проекта. Даты ориентировочные, привязаны к релизам.

---

## Фаза 1 — Ядро (текущее + багфиксы)

| Задача | Сложность | Зависимости | Критичность |
|--------|-----------|-------------|-------------|
| Unified adapter interface (`ProductSnapshot`) | M | — | Высокая |
| Миграция Ozon/WB адаптеров на `ProductSnapshot` | M | Unified adapter | Высокая |
| Исправление ошибок парсинга из текущего issue-трекера | S | — | Критическая |
| Стабилизация circuit breaker и adaptive cooldown | M | — | Высокая |
| Покрытие тестами текущих парсеров (unit + integration) | L | — | Высокая |
| Очистка дублирующегося кода между `parsers/` и `adapters/` | M | Unified adapter | Средняя |

**Цель фазы:** стабильное, протестированное ядро с единым форматом данных.

## Фаза 2 — Локальный API и управление сбором данных (один оператор)

| Задача | Сложность | Зависимости | Критичность |
|--------|-----------|-------------|-------------|
| FastAPI-каркас с healthcheck и OpenAPI | S | — | Высокая |
| REST API: запуск задач парсинга | M | FastAPI-каркас, Jobs & Attempts | Высокая |
| REST API: список товаров + история цен | M | FastAPI-каркас | Высокая |
| REST API: экспорт CSV/Excel по API | S | FastAPI-каркас | Средняя |
| Локальный режим по умолчанию: bind на localhost, безопасные CORS origins | S | FastAPI-каркас | Высокая |
| Защита от случайного запуска дублирующих задач парсинга | M | Jobs & Attempts | Высокая |
| API-документация (Swagger/ReDoc) | S | FastAPI-каркас | Низкая |

**Цель фазы:** удобное локальное управление парсингом, товарами, историей цен и экспортом для одного оператора. Пользовательская авторизация, JWT/OAuth2 и RBAC не входят в текущий scope.

## Обозначения сложности

| Код | Оценка | Описание |
|-----|--------|----------|
| **S** | 0.5–2 дня | Один файл, минимальная логика |
| **M** | 3–7 дней | Несколько файлов, не тривиальная логика |
| **L** | 2–4 недели | Архитектурные изменения, интеграции |
| **XL** | 1–3 месяца | Системные изменения, требующие рефакторинга |

---

## Ключевые решения (открытые)

- **Очередь задач:** Celery + Redis vs ARQ (AsyncResult). Выбор — ARQ для полного async, Celery если нужна совместимость с существующим стеком.
- **Dashboard:** React + Next.js vs lightweight (htmx + Jinja2). Для MVP — htmx, для SaaS — React.
- **Режим использования:** один оператор, локальная установка; многопользовательская авторизация и SaaS-функции не планируются без отдельного решения.
