# Bot Workflows

Подробное описание workflow для каждой команды Telegram-бота MarketMind AI.

---

## Добавление товаров

### `/add` — Добавить товары по ссылкам

**Что делает:** Принимает URL-ссылки на товары маркетплейсов (Ozon, Wildberries, Yandex Market, FunPay), парсит данные и добавляет в базу для мониторинга.

**Входные данные:**
- Один или несколько URL (по одному на строку)
- Поддерживаемые домены: `ozon.ru`, `wildberries.ru`, `market.yandex.ru`, `funpay.com`
- FSM: команда переводит в состояние `waiting_urls`, ожидает следующее сообщение с ссылками

**Выход:**
- Добавленные товары в БД с текущей ценой и статусом
- Прогресс-сообщения в чат по мере парсинга
- Итоговое сообщение: сколько добавлено, ошибок, дублей

**Ошибки:**
- Неподдерживаемый домен — сообщение «Неподдерживаемый маркетплейс»
- Блокировка парсинга — статус `blocked`, товар добавлен без цены
- Таймаут парсинга — retry через resilience module
- Пустой URL — пропуск строки

**Модули:** `bot.py` -> `worker.py` -> `parsers/router.py` -> `parsers/*.py` -> `database.py`

---

### `/wb` — Добавить товар с Wildberries

**Что делает:** Эксплицитный вариант `/add` для Wildberries. Парсит через API (без браузера).

**Входные данные:**
- URL товара WB или nm id
- FSM: состояние `waiting_urls`

**Выход:** Аналогичен `/add`, но только для WB.

**Модули:** `bot.py` -> `worker.py` -> `parsers/wildberries.py` -> `database.py`

## Обновление и мониторинг

### `/update` — Обновить цены

**Что делает:** Обновляет цены и наличие всех отслеживаемых товаров. После обновления — проверяет аномалии и рассылает уведомления подписчикам.

**Входные данные:** Не требует (команда без аргументов)

**Выход:**
- Прогресс-сообщения по мере обновления
- Итог: сколько обновлено, ошибок, изменений цен
- Уведомления подписчикам при изменениях

**Ошибки:**
- Массовая блокировка — adaptive cooldown через `resilience.py`
- Сетевые ошибки — retry с backoff

**Модули:** `bot.py` -> `worker.py` -> `updater.py` -> `parsers/*.py` -> `database.py` -> `resilience.py`

---

### `/list` — Список товаров

**Что делает:** Показывает все отслеживаемые товары с текущими ценами, статусами и процентом изменения.

**Входные данные:** Не требует

**Выход:** Форматированный список товаров в Telegram-сообщении.

**Модули:** `bot.py` -> `database.py` -> `telegram_messages.py`

---

### `/status` — Статистика базы данных

**Что делает:** Показывает общую статистику: количество товаров, последнее обновление, распределение по маркетплейсам.

**Входные данные:** Не требует

**Выход:** Сводка по БД.

**Модули:** `bot.py` -> `database.py` -> `telegram_messages.py`

## Поиск и сравнение

### `/search` — Поиск товара

**Что делает:** Ищет товары по названию на Ozon через Playwright.

**Входные данные:**
- Поисковый запрос (текст)
- FSM: состояние `waiting_search`

**Выход:**
- Список найденных товаров с ценами
- Возможность выбрать товар для добавления

**Ошибки:**
- Блокировка поиска Ozon — сообщение о недоступности
- Нет результатов — сообщение «Ничего не найдено»

**Модули:** `bot.py` -> `searcher.py` -> `updater.py`

---

### `/compare` — Сравнить цены

**Что делает:** Сравнивает цены одного товара между маркетплейсами (Ozon vs WB vs Yandex Market).

**Входные данные:**
- URL товара или название
- FSM: состояние `waiting_compare`

**Выход:**
- Таблица сравнения цен по маркетплейсам
- AI-рекомендация где дешевле

**Модули:** `bot.py` -> `agent.py` -> `parsers/router.py`

## Карточки Ozon

### `/ozon_card` — Подготовить карточку Ozon

**Что делает:** Генерирует черновик карточки Ozon из свободного текста или URL товара.

**Входные данные:**
- Свободный текст с описанием товара, или URL товара
- FSM: состояние `waiting_ozon_card`

**Выход:**
- XLSX файл с карточкой
- JSON с данными карточки
- AI-обогащение (если доступен AI provider)

**Ошибки:**
- Не удалось извлечь данные — fallback на ручной ввод
- AI недоступен — карточка без AI-обогащения

**Модули:** `bot.py` -> `card_filler.py` -> `card_profiles.py` -> `ai_client.py` -> `exporter.py`

---

### `/ozon_batch_cards` — Пачка карточек

**Что делает:** Генерирует пакет карточек Ozon из multiline текста или загруженного файла.

**Входные данные:**
- Multiline текст (одна строка = один товар)
- Или `.txt`/`.csv` файл
- FSM: состояние `waiting_ozon_batch`

**Выход:**
- Batch XLSX файл
- Batch JSON файл
- Summary: сколько успешно, ошибок

**Ошибки:**
- Файл не UTF-8 — сообщение об ошибке
- Пустые строки — пропуск
- Один bad item не ломает весь batch

**Модули:** `bot.py` -> `card_filler.py` -> `exporter.py`

---

### `/card_research` — Исследование карточки

**Что делает:** Анализирует конкурентов для указанного товара и формирует отчёт.

**Входные данные:**
- URL товара или описание
- FSM: состояние `waiting_card_research`

**Выход:**
- Отчёт по конкурентам: цены, описания, ключевые слова
- Рекомендации по SEO и позиционированию

**Модули:** `bot.py` -> `telegram_card_research.py` -> `searcher.py` -> `ai_client.py`

---

### `/make_card_last` — Карточка по последнему товару

**Что делает:** Генерирует карточку Ozon на основе последнего добавленного товара.

**Входные данные:** Не требует ( берёт последний товар из БД)

**Выход:** Аналогичен `/ozon_card`.

**Модули:** `bot.py` -> `card_filler.py` -> `database.py`

---

### `/profile` — Профиль карточек

**Что делает:** Показывает текущий профиль или переключает профиль карточек для текущего чата.

**Входные данные:**
- Без аргументов — показать текущий профиль и список доступных
- С именем (`/profile electronics`) — переключить профиль

**Выход:**
- Текущий профиль

## Диагностика

### `/metrics` — Последние попытки парсинга

**Что делает:** Показывает последние N попыток парсинга с статусами и latency.

**Входные данные:**
- Необязательный аргумент: количество записей (по умолчанию 20)

**Выход:** Таблица с URL, marketplace, source, status, latency.

**Модули:** `bot.py` -> `database.py` -> `telegram_messages.py`

---

### `/blocks` — Anti-bot и block memory

**Что делает:** Показывает adaptive block memory: какие URL/block patterns были обнаружены, текущие cooldown.

**Входные данные:**
- Необязательный аргумент: количество записей

**Выход:** Диагностика block patterns, strategies, cooldown.

**Модули:** `bot.py` -> `database.py` -> `telegram_messages.py`

---

### `/health` — Состояние маркетплейсов

**Что делает:** Показывает состояние каждого маркетплейса: heat score, source scores, cooldown.

**Входные данные:** Не требует

**Выход:** Сводка по здоровью маркетплейсов.

**Модули:** `bot.py` -> `database.py` -> `telegram_messages.py`

**Что делает:** Выполняет DNS/TCP/HTTPS пробы к api.telegram.org, показывает masked proxy.

**Входные данные:** Не требует

**Выход:** Результаты проб: DNS resolution, TCP connection, HTTPS handshake, proxy status.

**Модули:** `bot.py` -> `telegram_diagnostics.py`

## Safety expectations

- Если маркетплейс блокирует парсинг, бот генерирует fallback draft из URL/title где возможно.
- Если поиск конкурентов недоступен, генерация продолжается с локальным draft.
- `required_attributes` из профиля enforced как плейсхолдеры (`"нужно заполнить"`).
- FSM state очищается после завершения или ошибки.
- Parser lock предотвращает одновременный парсинг из разных команд.
- Adaptive cooldown предотвращает hammering заблокированных URL.
